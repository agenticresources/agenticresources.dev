Agentic Resources The independent reference for Agentic Resource Discovery: what it is, how to publish, a validator that runs in your browser, and the adoption numbers measured rather than asserted.

ARD is how an agent finds a capability before it calls one. You describe your MCP servers, agents, skills and APIs once, in a file on your own domain. Registries crawl those files and answer natural-language queries against them. MCP tells an agent how to call a tool; ARD tells it which tool exists and where.

01 — Read this first

The spec says ard.json. The web still says ai-catalog.json.

⚠ The path split

Version 0.91 renamed the manifest from /.well-known/ai-catalog.json to /.well-known/ard.json. Consumers must fetch the new path and may fall back to the old one. The deployed base has not followed: in our own probe of 50 domains on 4 September 2026, every one of the 31 publishers we found serves the old path, and only 6 also serve the new one. Neuronto's larger census reports the same shape: 182 of 207 publishers on ai-catalog.json, 25 on ard.json.

What to do: serve the identical manifest at both paths until the rename settles. A conformant consumer will find you on ard.json; everything built before late August will find you on ai-catalog.json. Any tool that checks only the new path will tell you almost nobody has adopted ARD. That is a measurement error, not a fact.

The specification is nine days old at v0.91 and still carries Proposal status. Expect further change, and treat any third-party guide, this one included, as potentially stale. Every claim on this page names the version and date it was checked against.

02 — What ARD is

A search engine layer for capabilities, with the index built from files you host

Today an agent can only use tools somebody wired into it by hand. ARD is the missing discovery surface: publishers describe resources under their own domain, registries index those descriptions, and a client asks a registry in plain language for the capability it needs. Domain ownership is the trust anchor, the way it is for email and the web.

1 · Publish

Describe what you offer

One JSON-LD manifest on your domain lists your MCP servers, A2A agents, skills, APIs and workflows, each with a few example queries it answers well.

2 · Index

Registries crawl it

Any ARD registry, public or private, fetches manifests and builds a semantic index. Enterprises run their own and merge internal, vendor and public results.

3 · Search

Agents ask, then connect directly

A client sends POST /search with natural-language text and filters, gets ranked entries back, and calls the winner over its native protocol. The registry never sits in the call path.

ARD is not a competitor to MCP or A2A. It sits one step earlier, and hands off to them.

03 — Publish

A minimal manifest

A manifest is a JSON document with an entries array. Each entry is a JSON-LD node and needs four things: a domain-anchored identifier, a displayName, a type given as an IANA media type, and exactly one of url or data. Add two to five representativeQueries or registries cannot rank you.

{
  "entries": [
    {
      "@context": "https://agenticresourcediscovery.org/context/v1",
      "identifier": "urn:air:example.com:server:invoices",
      "displayName": "Invoice Tools",
      "type": "application/mcp-server-card+json",
      "url": "https://example.com/.well-known/mcp/server-card.json",
      "description": "Create, send and reconcile invoices.",
      "representativeQueries": [
        "send an invoice to a customer",
        "check whether invoice 4021 was paid",
        "reconcile last month's receivables"
      ],
      "capabilities": ["CreateInvoice", "InvoiceStatus", "Reconcile"],
      "version": "1.2.0",
      "updatedAt": "2026-09-04T09:00:00Z"
    }
  ]
}

Serve it at https://example.com/.well-known/ard.json and /.well-known/ai-catalog.json with Content-Type: application/json. Add <link rel="ard" href="/.well-known/ard.json"> to your home page's <head>.

The identifier

Identifiers take the form urn:air:<publisher>:<namespace>:<name>, where the publisher is a fully-qualified domain you control. The prefix is air, not ard. A verifying registry rejects an entry claiming urn:air:google.com:… unless the entry's trustManifest.identity can prove it was issued by google.com. That is the whole defence against namespace squatting.

Media types you will actually use

TypeForRegistration
application/mcp-server-card+jsonAn MCP server, pointing at its server cardde-facto, IANA pending
application/a2a-agent-card+jsonAn A2A agent, pointing at its agent cardde-facto, IANA pending

The spec asks intermediaries not to verify these values strictly while registration is pending.

    05 — Field reference

    Every term in the base context

    Terms written without a prefix belong to the default namespace, https://agenticresourcediscovery.org/ns#. An entry may declare extra namespaces in its @context and use prefixed terms from them; registries index what they recognise and preserve the rest.

    TermTypeReq.Purpose
    identifierstringMUSTDomain-anchored URN, urn:air:<publisher>:<namespace>:<name>. The stable identity of the resource.
    displayNamestringMUSTHuman-readable name shown in registry results.
    typestringMUSTIANA media type identifying what kind of artifact this is.
    url@idMUST*Where the artifact document lives (the server card, agent card, OpenAPI file).
    data@jsonMUST*The artifact inline, as the alternative to url. Never both.
    representativeQueriessetSHOULDTwo to five natural-language queries this resource serves well. Registries build their semantic index from these. Missing or mis-sized is a conformance warning, not an error, but an entry without them will not be found by search.
    capabilitiessetMAYShort skill or tool tokens for fast structured filtering without fetching the artifact.
    descriptionstringMAYProse summary.
    tagssetMAYFree-form labels; filterable.
    versionstringMAYVersion of the resource described.
    updatedAtxsd:dateTimeMAYWhen the entry last changed; lets registries sync incrementally.
    metadata@jsonMAYArbitrary publisher-defined JSON. Dot-paths into it are filterable if the registry indexes them.
    trustManifest@jsonMAYIdentity, attestations, provenance and signatures. ARD reads only identity, which must align with the URN's publisher domain; the framework declared in trustSchema defines verification.
    @contextIRI / objectMAYOptional in the file; consumers apply the base context regardless. Include it when the entry may be read by generic JSON-LD tooling, especially in-page.
    @idIRIMAYJSON-LD node id. If present alongside identifier, both must denote the same resource.

    * Exactly one of url or data. Schema source: ard-entry.schema.json, which deliberately sets additionalProperties: true.

    06 — How discovery works

    Two layers, five publishing routes

    ARD separates static publishing from dynamic indexing. You publish; registries crawl and expose search. Most coverage mentions only the well-known file. The spec defines five routes, and a consumer is only required to honour two of them.

    Static — how you advertise

    RouteConsumer obligationHow
    Well-known URIMUST fetchhttps://{domain}/.well-known/ard.json, a manifest with an entries array.
    HTML link tagMUST honour<link rel="ard" href="…"> in a document's <head>.
    In-page JSON-LDMAYEntry embedded in the page describing the resource, found by ordinary crawling.
    Agentmap directiveMAYAgentmap: https://example.com/entries.json in robots.txt, by analogy with Sitemap.
    DNSMAYService Binding records at _entries._agents.example.com or _search._agents.example.com.

    Dynamic — how registries serve

    EndpointRequiredWhat it does
    POST /searchMUSTRanked entries for natural-language text plus optional filter. Federation modes auto, referrals, none. The score is relevance only and must never be read as trust.
    POST /exploreMAYFacet breakdowns over the matched set. Scoped to one registry; does not federate. 501 if unimplemented.
    GET /agentsMAYDeterministic browsing with structured filters, sorting and pagination, for developer portals.

    Only /search is mandatory. A registry may additionally expose search as an MCP tool or A2A skill, returning the same entry model.

    07 — Adoption

    Measured, not asserted

    Every announcement describes ARD as industry-backed, which is true, and then implies it is widely deployed, which is a separate claim. Here is what has actually been counted, starting with our own probe. The method and the full domain list are published so you can repeat it.

    31 / 50 Domains serving a manifest · our probe

    Fifty domains fetched at both well-known paths on 4 September 2026: the 11 launch backers' root domains, the spec's own domain, a sample of known publishers, and a control group of large API companies.

    6 / 31 On the new ard.json path

    All 31 publishers serve ai-catalog.json. Six also serve ard.json. Nobody serves the new path alone.

    1 / 11 Launch backers publishing at their root

    Of Google, Microsoft, GitHub, Hugging Face, Cisco, Databricks, Nvidia, Salesforce, ServiceNow, Snowflake and GoDaddy, only huggingface.co serves a manifest at its root domain. GitHub publishes 251 entries at api.mcp.github.com. The spec's own domain serves none.

    Serving a manifest says nothing about trust, quality or conformance. Entry counts are the length of the entries array as fetched. Raw results: probe-2026-09-04.json.

    Larger censuses, by others

    SourceDomains checkedManifests foundNote
    Neuronto ARD Registry375,995246207 publishers with 2,215 declared resources. 182 on the old path, 25 on the new. Verified by fetching, not by trusting other registries.

    The three numbers disagree by two orders of magnitude because the crawl frames differ. Read the ratio, not the count: publishing is real but thin, and concentrated among developer-tool companies.

    Method and full domain list

    For each domain we fetched /.well-known/ard.json and /.well-known/ai-catalog.json over HTTPS with a 12-second timeout, following redirects, with the user agent agenticresources.dev-probe/0.1. A path counts as serving when it returns 200 and the body parses as JSON containing an entries array, an array of entries, or a single entry object.

    How to read this

    Thin publisher adoption nine days after a v0.91 proposal is unremarkable. The registry side shipped first: GitHub's Agent Finder, Hugging Face's Discover tool, Google Cloud Agent Registry and AWS Agent Registry all consume ARD today, so the incentive to publish is arriving from the platforms rather than from the spec. The honest comparison is llms.txt, a well-known-path convention that had enormous discourse and, for a long while, negligible adoption, and then became a default in framework tooling.

    These numbers are published here because nobody whose business depends on ARD succeeding is in a position to publish them.
